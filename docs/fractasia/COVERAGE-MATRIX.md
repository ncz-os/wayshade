# Xfractint 20.04p16 source catalogue

This is a source inventory, not a claim that the NCZ shader renders these types faithfully. It was derived from the [public Linux archive](https://www.fractint.org/ftp/current/linux/xfractint-20.04p16.tar.gz) (SHA-256 `4e5401cfec0e6ffa1dab38e3c177e1445772096cbe554200c512edeea23c47ad`). The source table is `common/fractalp.c:fractalspecific[]`; numeric IDs are checked against `headers/fractype.h`. The build chooses one of two `RANDOM_RUN` branches with the same two registrations. The disabled `#if 0` entry and terminal `NULL` sentinel are excluded. Names beginning with `*` are hidden from the type menu (`common/prompts1.c`).

**173 active type slots:** 107 menu-visible and 66 hidden numeric or internal registrations. There are 20 distinct rendering dispatch callbacks, 116 orbit callbacks and 169 distinct `(orbit, per_pixel, per_image, calctype)` callback combinations. Callback counts are implementation structure, not a count of mathematical algorithms. `StandardFractal` alone dispatches 117 registrations with different orbit/setup functions.

The source also exposes 31 selectable functions in `common/prompts1.c:trigfn[]`; suitable types can take up to four slots, giving up to 31⁴ = 923,521 selector tuples before numeric parameters. Formula (`.frm`), IFS (`.ifs`) and L-system (`.l`) inputs plus numeric parameters make the space of generatable images open-ended. A finite coverage denominator should therefore use the 107 visible built-in registrations, with hidden paths tracked separately.

The current NCZ program exposes 13 shader labels. No source-to-shader mathematical parity evaluation has been completed for this table. Its earlier 67/184 claim is withdrawn: 184 is not the active registration count, the old list mixed unrelated names and omissions, and a shared visual family does not prove the same algorithm. `MANDELBULB` and `MANDELBOX` are not registered in this archive.

## Acceptance rule

For each menu-visible type, verify the defining recurrence or state update, parameter semantics, bailout/termination, output colouring and representative rendered frames against the public reference. Hidden numeric paths need an explicit precision-equivalence decision. Mark a type supported only after those checks pass on target GPUs. A generic family shader, non-black frame or matching palette does not satisfy parity.
